## 本月学到的套路

- 定长滑动窗口：窗口右移只处理「尾部进 + 头部出」两件事，维护一个计数变量即可。
- 定长窗口最稳的单循环骨架：进 → `if (r >= k)` 出 → `if (r >= k - 1)` 收答案。
- 写循环时**下标语义要唯一**，别让「窗口右端」和「下一个待处理位」共用一个变量。
- **看到「长度恰好 k 的子数组」先想定长窗口**，但要注意定长只是必要条件：还得看窗口里维护的量能否 O(1) 增删。和/计数可以，元素极值/中位数不行（要单调队列或 `multiset`）。
- **题目问的量和你要维护的量往往不是一个**：1343 问平均值、维护和；2379 问涂色次数、维护白块数；2090 问半径、实际窗口长 `2k+1`。
- 数据处理三件套：平均值 → 乘过去（`sum >= k * threshold`）；范围/半径 → 先换算真实窗口长；答案位置 → 不一定是右端（2090 写回中心）。
- **窗口里可以同时维护多个量**（2841：`sum` + `cnt.size()`），判断能否滑的标准是「每个量单独能否 O(1) 增删」。
- **两段式拆解**：答案 = 与区间无关的固定部分 + 区间内增量。1052 总满意 = 本来就满意的人 + 窗口内救回的人。拆完两段都是 O(n)。
- **反模式**：滑窗里再套一层循环 / 向两侧扩 → 退化成 O(n²)。看到自己这么写，先回去检查拆解。
- **不定长窗口为什么一定最优**：每个右端点只需要一个最优左端点（合法性对收缩封闭），而这个左端点单调不减，所以摊还 O(n)。判据一句话——**窗口变大时合法性是否单向变化**。
- 求最长在「不合法」时缩、答案写在 `while` 外；求最短在「合法」时缩、答案写在 `while` 里。**这两句记反是滑窗最主要的 bug 来源**。
- **题目里的「必须」要落成减一**：1493 必须删一个元素，答案 `len - 1`；1004 最多翻 k 个，不减。
- 维护的量不一定可逆：窗口和可逆，窗口最大值不可逆；「去重和」看似不可逆，其实靠计数就能精确回退（3795）。
- **二分的产物是「切缝」不是「找到没」**：数组被 target 切成两段，二分找的是那条缝。判定条件写成哪个，就决定 `lo` 落在哪条缝上——`a[mid] >= t` 出左边界，`a[mid] > t` 出右边界（下一格），结果可以等于 `n`（插在末尾）。34 = 两条缝夹区间，35 = 直接要左边界。
- **区间写法我选双闭 [lo, hi]**：`lo`/`hi` 都是真实下标，`while (lo <= hi)` 语义直白；配套 `mid ± 1`，不变量是收尾时 `lo == hi + 1`。
- **计数型滑窗**：`ans += r - l + 1`，含义是「以 r 结尾的合法子数组个数 = 窗口长度」。求最长/最短是问「最优窗口多长」，求个数是问「所有窗口长度之和」。
- **二分是「在可排序的数组里查」的默认手段**：纯查边界用 `lower_bound`/`upper_bound`，答案不在数组里就自己定上下界（二分答案）。
- **前缀和识别信号**：需要反复用到「连续一段的和」时就该想它。它有两个身份——①把区间和变成两数之差（省计算）；②排序后 `pref` 天然递增，可以直接当二分的被查数组（制造单调性，2389）。
- **上取整 `(a + b - 1) / b`**（`a >= 0`）：把「比较式里有乘除」的问题挪到二分外面，先算阈值再二分一次比较（2300）。
- **迭代器 ≠ 指针地址**：`it - begin()` 是下标，相减已经是元素个数，`sizeof` 永远不参与。这是语法书「迭代器像指针」这句话的最大误导处。
