## 题意

给一个只含 `'U' 'D' 'L' 'R'` 的字符串 `s`（在无限二维网格上从 `(0,0)` 出发移动），再给正整数 `k`。

你必须**恰好删掉一个长度为 `k` 的连续子串**，然后从 `(0,0)` 开始按顺序执行剩下的移动。问能到达的**不同最终坐标**有多少个。

```
s = "LUL", k = 1
删 "L"(下标0) → "UL"  → (-1, 1)
删 "U"        → "LL"  → (-2, 0)
删 "L"(下标2) → "LU"  → (-1, 1)
不同终点：(-1,1)、(-2,0) → 2
```

数据范围：`n <= 10^5`，`1 <= k <= n`。

## 我的思路（这次是顺的）

第一步就要做那个关键的等价转换：**别去模拟「删掉之后再走一遍」**，那是 O(n²)。

```
设不删任何字符时终点是 C = (X, Y)
被删掉的那一段自身位移是 d = (dx, dy)
那么删掉之后的终点 = C - d
```

因为「少走的那段」等价于「在终点上把这个位移减掉」——路径的其余部分不受影响，删掉中间一段只是让后面的移动整体平移了 `-d`。

于是：`C` 对**所有**删除方案都是同一个常数，所以

> 两种删除方案的终点不同 ⟺ 被删掉那两段的位移 `d` 不同。

问题变成：**统计所有长度为 `k` 的窗口的位移 `(dx, dy)`，有多少个不同**。

这就是标准定长滑窗：窗口右移一格，进一个字符、出一个字符，位移用加减 O(1) 维护。

## 解法

```cpp
class Solution {
    pair<int,int> step(char c) {
        if (c == 'L') return {-1, 0};
        if (c == 'R') return { 1, 0};
        if (c == 'D') return { 0,-1};
        return {0, 1};                          // 'U'
    }
public:
    int distinctPoints(string s, int k) {
        int n = (int)s.size();
        long long base = 2LL * n + 1;           // 编码用的进制，够大就不会撞
        unordered_set<long long> seen;
        int x = 0, y = 0;
        for (int r = 0; r < n; ++r) {
            auto d = step(s[r]);
            x += d.first; y += d.second;        // 1 进
            int l = r - k + 1;
            if (l < 0) continue;                // 窗口还没满
            // 2 收：把 (x, y) 编码成一个 long long 再塞进哈希表
            seen.insert((long long)(x + n) * base + (y + n));
            auto o = step(s[l]);
            x -= o.first; y -= o.second;        // 3 出
        }
        return (int)seen.size();
    }
};
```

出窗一定要**减**，别把入窗那两句直接复用（这是唯一容易写反的地方）。

**为什么编码成 `long long` 而不是 `unordered_set<pair<int,int>>`**：标准库没给 `pair` 提供 `std::hash`，那样写编译不过。替代方案见「易错点」和 `专题/哈希表.md`。

## 复杂度

- 时间 O(n)：每个字符进出窗口各一次。
- 空间 O(n - k + 1)：最多存这么多个不同位移。

## 易错点

- **`k == n` 时窗口只有一个**，答案是 1，别写 `if (k >= n) return 0;`。
- **别模拟**：删掉长度为 k 的段再重走一遍是 O(n²)，n = 10^5 直接 TLE。这题的全部价值就在那个减法。
- 位移 `int` 就够（`|x| <= n <= 10^5`），但**编码时乘法会溢出 int**，`(x + n) * base` 必须转 `long long`。
- 编码要保证**不撞**：`x + n` 和 `y + n` 都落在 `[0, 2n]`，所以进制取 `2n + 1` 是单射。用 `<< 20` 也行（`2^20 > 2*10^5`），但硬编码的位数容易在别的题上出事。
- `unordered_set<pair<int,int>>` **编译不过**（不是运行错），报错信息长到看不懂。用 `set<pair<int,int>>`（能过，O(log n)）或编码/自定义 hash。
- 出窗是「减」，别把入窗的函数直接拿来用。

## 我的感想

思路是顺的，卡的全是语法，而且两次卡的是同一类问题：**「我脑子里想的数据结构，C++ 里没有现成的」**。

- 想要「以 pair 为键的哈希集合」→ 得知道 `std::hash` 只对基本类型和 `string` 等少数类型有特化，`pair` 没有。
- 想要「类里一个定长数组」→ 得知道类内成员初始化只能用 `=` 或 `{}`，`()` 是非法语法。

这两件事都不是算法问题，但都会让你在「思路已经完全想清楚」的状态下卡半小时。所以我把它们单独立成了清单（`专题/C++常用工具箱.md` 的「语法后悔药」一节）——**这类坑不值得第二次踩**。

另外一个收获是那个转换的**方向**：一般我们会想「删掉之后长什么样」，这题反过来想「**总位移减去被删段的位移**」。减法让「路径的其余部分」完全消失，只剩一个和位置无关的向量。**当一个操作让后面的东西整体平移时，先把它写成「常数 + 变量」的形式**，往往就能把 O(n²) 压到 O(n)。

## 更优解

不用算第一个窗口的真实位移，因为「不同」只关心差异：把第一个窗口记成 `(0,0)`，之后每步累加 `step(s[i]) - step(s[i-k])`，从 `i = k` 开始循环。少一次判空，常数更小。

```cpp
int x = 0, y = 0;
unordered_set<long long> seen;
seen.insert((long long)n * base + n);            // 第一个窗口的 (0,0) 编码
for (int i = k; i < n; ++i) {
    auto a = step(s[i]), b = step(s[i - k]);
    x += a.first - b.first;
    y += a.second - b.second;
    seen.insert((long long)(x + n) * base + (y + n));
}
```

复杂度同为 O(n)，但省掉了「窗口未满」的分支。
