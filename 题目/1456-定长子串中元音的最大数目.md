# 1456. 定长子串中元音的最大数目

## 题意

给字符串 `s` 和整数 `k`，返回所有**长度恰好为 k** 的子串中，元音字母（`a e i o u`）个数的最大值。

约束：`1 <= s.length <= 10^5`，`1 <= k <= s.length`。→ 必须 O(n)，不能枚举所有子串（那是 O(nk)）。

## 我的思路

定长滑动窗口：先把前 `k` 个字符装进窗口、数出元音个数，然后每次整体右移一格——**右端进来一个、左端出去一个**，窗口长度恒为 k，所以只需要维护「元音计数」这一个变量，不用每次重数。

这就是定长窗口的本质：**滑动时数据的变化只由「尾部进入的元素」和「头部离开的元素」决定**，O(1) 更新。

## 我的错误（首次提交 WA）

我用了两个循环共享同一个下标 `r`：

```cpp
int cnt = 0;
for (int r = 0; r < k; ++r)          // 初始化窗口 [0, k-1]
    if (isVowel(s[r])) ++cnt;
int ans = cnt;

for (; r < n; ) {
    ++r;                              // ← 错在这里
    if (isVowel(s[r]))   ++cnt;       // 进
    if (isVowel(s[r-k])) --cnt;       // 出
    ans = max(ans, cnt);
}
```

第一个循环结束时 `r == k`，**而 `s[k]` 正是下一个该进窗口的字符**。再 `++r` 就变成了 `s[k+1]`，`s[k]` 被整个跳过。

更糟的是：跳过之后 `r` 永远偏大 1，于是每一轮「进」的是 `s[r]`、「出」的是 `s[r-k]`，两者不再对应同一个窗口——**从第一次滑动开始，维护的计数就再也不是任何真实窗口的元音数了**。所以不是「只错了一个窗口」，而是后面全错。

> 诊断是对的，只是要说得更狠一点：不是「漏判断 s[k]」，而是**下标错位一格，整个窗口从此失效**。

## 正确写法

### 写法一：沿用两个循环，去掉 `++r`

```cpp
class Solution {
    bool isVowel(char c) {
        return c == 'a' || c == 'e' || c == 'i' || c == 'o' || c == 'u';
    }
public:
    int maxVowels(string s, int k) {
        int n = (int)s.size();
        int cnt = 0;
        for (int i = 0; i < k; ++i)          // 注意：换一个变量名 i
            if (isVowel(s[i])) ++cnt;
        int ans = cnt;

        for (int r = k; r < n; ++r) {        // r 直接从 k 开始，进的就是 s[k]
            if (isVowel(s[r]))   ++cnt;      // 尾部进
            if (isVowel(s[r - k])) --cnt;    // 头部出
            ans = max(ans, cnt);
        }
        return ans;
    }
};
```

关键点：**`for (int r = 0; r < k; ++r)` 结束时 `r == k`，这个值本身就已经是「下一个待处理下标」**。要么直接用它（不要 `++r`），要么干脆换个变量名，让两个循环互不干扰。

### 写法二：一个循环（我更推荐，不容易错）

```cpp
class Solution {
public:
    int maxVowels(string s, int k) {
        int n = (int)s.size(), cnt = 0, ans = 0;
        for (int r = 0; r < n; ++r) {
            if (isVowel(s[r])) ++cnt;              // 1. 右端无条件进
            if (r >= k && isVowel(s[r - k])) --cnt; // 2. 窗口超长了，左端出
            if (r >= k - 1) ans = max(ans, cnt);    // 3. 窗口刚好 k 个，更新答案
        }
        return ans;
    }
};
```

这个「进 → 超长就出 → 够长就收答案」的骨架对**所有定长窗口题**通用，把 `s[r-k]` 那一步的触发条件写成 `r >= k`，边界就不会错——因为判断条件和下标来源是同一个表达式，天然对齐。后面 `r` 从 0 一路走到 n-1，不存在「上个循环留下的值」这种隐形约定。

**复杂度**：时间 O(n)，空间 O(1)。

**一个免费优化**：`ans == k` 时直接返回，因为不可能更大了（最多全是元音）。

## 易错点

- **跨循环复用下标**：上一个循环结束时 `r` 已经越过了它遍历的范围，这个「多出来的 1」是隐形约定，最容易错。（本题的全部原因）
- 初始化窗口写成 `[0, k]`（多了 1 个），或者 `for (int i = 0; i <= k; ++i)`。
- 「进」和「出」的顺序：只要本轮记录答案之前两个都做完，顺序无所谓；但如果写成了 `ans = max(...)` 夹在中间，就会拿到长度 k+1 或 k-1 的窗口。
- 元音判断漏 `u`，或者把 `y` 也算进去。
- `k == n` 时第二个循环不执行，答案必须来自初始化那一步——别忘了这一支。

## 我的感想

我一开始把「窗口右移」想成了「`r` 先加一，再用 `r`」，但在两个循环的结构里，`r` 在第一次循环结束时**已经**加到了 k。这说明我脑子里跑的是「`r` 指向当前窗口右端」，而代码里 `r` 实际是「循环变量、指向还没处理的位置」——**同一个名字，两种语义**，于是错位。

教训：**下标变量的含义要唯一**。「当前窗口右端」和「下一个待处理元素」是两个概念，别共用一个变量。写法二之所以稳，就是因为它从头到尾只有一种语义。

## 更优解 / 其他思路

- 前缀和：`pref[i]` = 前 i 个字符的元音数，答案 = `max(pref[i+k] - pref[i])`。也是 O(n)，但要多 O(n) 空间，且失去了「滑动」的意义，不推荐。
- 早停：`ans == k` 直接返回。
- 元音判断可以换成 `string("aeiou").find(c) != string::npos`，或者打一张 128 的表，但三个 `||` 已经够快。
