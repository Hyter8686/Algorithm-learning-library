# 1052. 爱生气的书店老板

## 题意

`customers[i]` 是第 i 分钟来的顾客数，`grumpy[i] == 1` 表示老板这一分钟在生气（顾客不满意地离开），否则满意。老板能连续 `minutes` 分钟不生气（只有一次机会）。求最多能让多少顾客满意。

## 我的思路（走过的弯路）

第一反应是「以每个窗口为起点，用 `while` 向两侧找本来就是 0 的位置加上，再比较」——相当于模拟「老板在这段不生气」的效果，每个窗口都重新扫一遍。**复杂度 O(n²)**，78 个用例里挂了 2 个（超时）。

**为什么慢**：定长窗口的价值就在于「滑一格只更新两端的进出」，而我每个窗口都在重新遍历窗口内部 + 向外扩，等于放弃了滑窗的全部优势。凡是写出「窗口内再套一层循环/while」的定长窗口，基本都要警惕是不是退化成 O(n²)。

## 正确思路：两段式分解

把「总满意人数」拆成**与窗口无关的部分** + **窗口能带来的增量**：

```
总满意 = 本来就满意的人（grumpy == 0，全部计入）
       + 让窗口内「原本不满意的人」变满意带来的增量
```

- 前半部分是**固定的**，和窗口选在哪无关，直接 `for` 一遍累加，O(n)。
- 后半部分是一次**定长窗口**：窗口长度 `minutes`，窗口内「收益」定义为 `grumpy[i] == 1 ? customers[i] : 0`，求这个收益的最大窗口和，O(n)。

两段相加就是答案。

## 代码

```cpp
class Solution {
public:
    int maxSatisfied(vector<int>& customers, vector<int>& grumpy, int minutes) {
        int n = (int)customers.size();
        int base = 0;
        for (int i = 0; i < n; ++i)
            if (grumpy[i] == 0) base += customers[i];   // 第一段：本来就满意

        int gain = 0, best = 0;
        for (int r = 0; r < n; ++r) {                   // 第二段：定长窗口
            if (grumpy[r]) gain += customers[r];        // 进（只有生气的人有收益）
            if (r >= minutes && grumpy[r - minutes])
                gain -= customers[r - minutes];         // 出
            if (r >= minutes - 1) best = max(best, gain);
        }
        return base + best;
    }
};
```

**复杂度**：时间 O(n)，空间 O(1)。

## 关键点：为什么可以这么拆

「老板选一段不生气」这件事，只影响**这一段里的人**：原本生气的人变成满意（收益 `customers[i]`），原本满意的人不受影响。所以总满意度 = 不受影响的固定部分 + 这一段带来的收益。收益只在这一段里累加，天然适合滑窗。

**拆的前提**：影响是「局部且可加」的。如果「老板不生气」还会影响其他分钟（比如顾客会改天再来），就不能这么拆了。

## 易错点

- 把「本来满意的人」也算进窗口收益，导致重复计数（正确做法是窗口只统计 `grumpy[i] == 1` 的人）。
- 窗口长度用 `minutes` 还是 `minutes - 1` 搞错（「连续 `minutes` 分钟」= 窗口长度 `minutes`）。
- 写出「每个窗口重新扫一遍」的 O(n²) 版本——这题 n 只有 2×10^4，O(n²) 是 4×10^8，刚好卡超时。
- `gain` 求最大，初始化为 `0` 是对的（可以一分钟都不救，收益为 0），别写 `INT_MIN`。
- 用两个数组做「预处理收益数组」也对，但没必要多开 O(n) 空间。

## 我的感想

这题花的时间最长，但收获也最实在：**先想「答案由哪几块拼成」，再决定哪一块用滑窗**。我第一版是「直接反过来模拟」，把窗口当成了「起点」，于是每个窗口都要往外找；正确解是把不变量（本来就满意的人）先摘出去，剩下的才是窗口该管的事。

另外一个教训：**滑窗题里出现「向两侧找」「窗口内再循环」，几乎一定是思路没拆干净**。定长窗口只允许「进一个、出一个」这种 O(1) 动作。

## 更优解 / 其他思路

- 预处理 `satisfied[i] = grumpy[i] ? 0 : customers[i]`，前缀和求固定部分，再对 `loss[i] = customers[i] - satisfied[i]` 做定长窗口。等价，但多两个数组。
- 把两段写进同一个循环（省一次遍历），可读性下降，不建议。
