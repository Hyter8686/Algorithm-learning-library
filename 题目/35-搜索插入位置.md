## 题意

升序**无重复**数组 `nums` 和目标 `target`，存在就返回下标；不存在就返回它**应该被插入的位置**（保持有序）。

```
输入: [1,3,5,6], target = 5  → 2
输入: [1,3,5,6], target = 2  → 1
输入: [1,3,5,6], target = 7  → 4
输入: [1,3,5,6], target = 0  → 0
```

## 我的思路

这题是二分里「**失败也有意义**」的第一个例子。

我一开始按 704 的三路写法写：`==` 就 return，`<` 往右，`>` 往左，最后 `return lo`——能过，但心里没底，因为「`lo` 凭什么就是插入位置」是猜的。

后来推演了一遍，发现严格来说它求的是：**第一个 ≥ target 的下标**。

- 找到了：第一次出现的那个位置就是它（本来就有序、无重复）。
- 没找到：就是「比 target 大的那些数里最小的一个」的位置，也就是新元素该放的地方。
- `target` 比所有数都大：`lo` 一路走到 `n`，正好是追加到末尾的位置。

想通这个以后，**连 `==` 分支都可以删掉**——精确查找是「找边界 + 核对」的特例，而边界本身就是答案。这也正是题目名叫「搜索插入位置」的原因：它问的压根不是「在不在」。

## 解法（双闭区间，只写两路分支）

```cpp
int searchInsert(vector<int>& nums, int target) {
    int lo = 0, hi = (int)nums.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (nums[mid] >= target) hi = mid - 1;   // mid 可能是答案，往左找更早的
        else                     lo = mid + 1;   // mid 太小，答案在右边
    }
    return lo;      // 循环结束时 lo == hi + 1，这是第一个 >= target 的位置，取值 [0, n]
}
```

**关键不变量**：循环结束时 `lo == hi + 1`，且

- `[0, lo)` 里的元素全都 `< target`；
- `[lo, n)` 里的元素全都 `>= target`。

所以 `lo` 天然就是「第一个不小于 target 的位置」，既是插入位置，也是 `lower_bound` 的返回值。`lo` 可以是 `n`（全小于 target 时），题目允许——正好是插到末尾。

## 复杂度

- 时间 O(log n)，空间 O(1)。

## 易错点

- **用 `>` 而不是 `>=`**：写成 `nums[mid] > target` 求的是「第一个 > target」，target 存在时会插到它**后面**，答案错。这是本题最典型的错法。
- 结束后返回 `lo` 还是 `lo - 1`：想清楚不变量再写。`lo` 是第一个 `>= target` 的，`lo - 1` 是最后一个 `< target` 的，别混。
- 双闭写法里 `hi = mid - 1` 不能写成 `hi = mid`，否则死循环。
- 别特判「比所有数大」返回 `n`——`lo` 自己就会走到 `n`，特判反而是冗余。

## 我的感想

这题是我对二分理解的分水岭。

之前的认知是「二分要么找到，要么返回 -1」。这题告诉我：**二分的产物不是「找没找到」，而是「分界点」**。数组被 `target` 切成两段（`< target` 和 `>= target`），二分是在找那条**切缝**。切缝存在与否跟 target 在不在数组里无关——它永远存在。

于是「找到」变成了「切缝右边第一个元素恰好等于 target」这种附加信息，二分本体根本不需要关心。34 题就是拿两条切缝（`>= target` 和 `> target`）夹出一个区间。

另外我发现判定符号的差别可以直接看出答案落在哪：

| 写法 | 求出的 `lo` |
| --- | --- |
| `if (a[mid] >= target) hi = mid - 1;` | 第一个 **≥ target** 的位置 |
| `if (a[mid] > target) hi = mid - 1;` | 第一个 **> target** 的位置 |

前者是 target 的**左边界**，后者减一就是**右边界**。换句话说：`>=` 出第一个，`>` 出最后一个（的下一格）。记住这一条，34、35 都不用背模板了。

## 更优解

O(log n) 最优。等价写法：

```cpp
return (int)(lower_bound(nums.begin(), nums.end(), target) - nums.begin());
```

一行，但只适合这种能直接用 STL 的场景。
