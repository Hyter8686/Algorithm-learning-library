## 题意

升序数组（**可能有重复**）和目标 `target`，返回 `target` 第一次和最后一次出现的下标；不存在返回 `[-1, -1]`。要求 O(log n)。

```
输入: nums = [5,7,7,8,8,10], target = 8  → [3,4]
输入: nums = [5,7,7,8,8,10], target = 6  → [-1,-1]
输入: nums = [], target = 0             → [-1,-1]
```

## 我的思路

35 让我明白二分求的是「切缝」，这题就是**找两条切缝**：

- 左边界 = 第一个 `>= target` 的位置；
- 右边界 = 第一个 `> target` 的位置，再减一。

而这两条切缝，**只差判定符号**：

```cpp
if (a[mid] >= target) hi = mid - 1;   // 找第一个 >= target
if (a[mid] >  target) hi = mid - 1;   // 找第一个 >  target
```

同一份骨架，换个比较符就换了个边界——这是我这轮最想记下来的一句。为什么？因为整套二分的不变量是：

> 循环结束时 `lo == hi + 1`，且 `[0, lo)` 全部满足「往左缩的条件」，`[lo, n)` 全部不满足。

「往左缩的条件」写成 `a[mid] >= target`，`lo` 就是左边界；写成 `a[mid] > target`，`lo` 就是右边界 + 1。**判定条件就是你要的边界的定义式**，不是要背的两套模板。

拿到 `l` 之后不要急着返回，先验一下 `l` 是否越界（`l == n`）以及 `nums[l]` 是否真的等于 `target`——毕竟「第一个 ≥ target 的位置」在 target 不存在时也是有值的，那是插入位置，不是答案。

## 解法

```cpp
// 返回第一个 >= t 的位置，范围 [0, n]
int firstGE(vector<int>& a, int t) {
    int lo = 0, hi = (int)a.size() - 1;          // 双闭 [lo, hi]
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] >= t) hi = mid - 1;           // mid 满足，记下后在左半边继续找
        else             lo = mid + 1;
    }
    return lo;                                   // lo == hi + 1
}

// 返回第一个 > t 的位置，范围 [0, n]
int firstGT(vector<int>& a, int t) {
    int lo = 0, hi = (int)a.size() - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        if (a[mid] > t) hi = mid - 1;
        else            lo = mid + 1;
    }
    return lo;
}

vector<int> searchRange(vector<int>& nums, int target) {
    int n = (int)nums.size();
    int l = firstGE(nums, target);
    if (l == n || nums[l] != target) return {-1, -1};   // 不存在
    int r = firstGT(nums, target) - 1;                  // 右边界
    return {l, r};
}
```

两个函数其实可以合成一个，传个 `bool` 或者把谓词抽成 lambda，但**分开写更不容易错**，我选分开。

不必担心 `n == 0`：`hi = -1`，循环不进，`lo = 0`，`l == n == 0` 直接返回 `{-1,-1}`。

## 复杂度

- 时间 O(log n)（两次二分），空间 O(1)。

## 易错点

- **别用 `target + 1` 求右边界**：target 是 `INT_MAX` 时溢出（虽然本题数据范围安全，但这是坏习惯）。用 `firstGT` 干净。
- 求出 `l` 后不验证就返回 → target 不存在时返回 `{插入位置, 插入位置 - 1}`，看起来还挺像那么回事。
- 验证写成 `nums[l] != target` 忘了先判 `l == n` → 越界。
- 右边界写成 `firstGT - 1` 还是 `firstGE - 1`：前者是「最后一个 ≤ target」，后者是「最后一个 < target」，**这题要的是前者**。
- 不要拿 `found` 标志在循环里 `break` 出去再左右扩——那是 O(n)，面试官一眼看穿。

## 我的感想

这题把 35 的收获彻底落实了：**二分没有「找元素」和「找边界」之分，只有「你在找哪条切缝」**。

以前我觉得「第一个/最后一个位置」是特殊需求，得写特殊代码。现在看就是同一份代码跑两遍、改一个符号。原来那种「找到 target 后往两边 while 扩展」的写法之所以被淘汰，是因为它把 O(log n) 的定位退化成了 O(n) 的扫描——而二分本来就同时告诉了你边界在哪，白给的信息不用太亏。

另外一个小认识：**`lo` 的取值是 `[0, n]` 共 n+1 种可能**，比下标多一个。这个「多出来的 n」不是 bug，是「插在末尾」这个合法答案。所有「第一个 ≥ x」的问题都有这个特性，判越界的时候记住它是 `l == n` 而不是 `l == n - 1`。

## 更优解

两次二分已是 O(log n) 最优。STL 版：

```cpp
auto l = lower_bound(nums.begin(), nums.end(), target);
auto r = upper_bound(nums.begin(), nums.end(), target);
if (l == r) return {-1, -1};
return {(int)(l - nums.begin()), (int)(r - nums.begin()) - 1};
```

`l == r` 就说明区间为空，等价于我上面的验证，还挺优雅。
