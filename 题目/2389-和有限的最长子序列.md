## 题意

给数组 `nums` 和查询数组 `queries`。对每个 `queries[i]`，求 `nums` 中**元素和 ≤ queries[i]** 的**子序列**的**最大长度**。

注意是**子序列**——可以跳过任意元素、任意挑，不用连续。

```
输入: nums = [4,5,2,1], queries = [3,10,21]
输出: [2,3,4]
解释: q=3  → 选 [2,1]，和 3，长度 2（选 3 个数最少是 1+2+4=7 > 3）
     q=10 → 选 [1,2,4]，和 7，长度 3
     q=21 → 全选，和 12，长度 4
```

## 我的思路

关键一步是**看出「子序列」让问题变简单**：既然可以任意挑，那为了在同样和的限制下塞进尽量多的数，就应该**从小到大挑**——这是直觉，也是严格的交换论证（如果选了一个大数而漏了一个更小的数，把大数换成小数，长度不变、和更小，只会更容易满足）。

所以：

1. 把 `nums` **升序排序**；
2. 排序后「挑 k 个最小的数」就是前缀的前 k 个 → 做前缀和；
3. 对每个 query，在**严格递增**的前缀和数组里找「最后一个 ≤ query 的位置」`k`，那就是最大长度。

第 3 步是二分：`upper_bound(pref, q) - 1`，也就是 `firstGT(q) - 1`。

## 核心细节：前缀和的下标必须开 n+1

我第一版就死在这里——**漏了最后一个数的和**。原因是我写成了

```cpp
vector<int> pref(n);                      // 错：只有 n 个位置
for (int i = 0; i < n; ++i) pref[i] = (i ? pref[i-1] : 0) + nums[i];
```

`pref[k]` 表示「前 k 个数的和」，`k` 要能取到 `n`，所以数组必须有 `n+1` 个位置、`pref[0] = 0`。写成 `pref[n]` 表示「前 n 个」时就会越界；而如果用小一号的数组硬凑，最后一个前缀就存不下来——症状就是「选全部」的查询答案永远少 1。

**记忆点**：任何「前 k 个」的量，下标域是 `[0, n]`，长度 `n+1`。和二分边界落在 `[0, n]` 是同一件事。

## 解法

```cpp
vector<int> answerQueries(vector<int>& nums, vector<int>& queries) {
    sort(nums.begin(), nums.end());
    int n = (int)nums.size();

    vector<long long> pref(n + 1, 0);              // pref[k] = 前 k 个（最小）元素之和
    for (int i = 0; i < n; ++i) pref[i + 1] = pref[i] + nums[i];

    vector<int> ans;
    ans.reserve(queries.size());
    for (int q : queries) {
        // pref 严格递增（nums[i] >= 1），找最后一个 <= q 的下标
        int k = (int)(upper_bound(pref.begin(), pref.end(), (long long)q) - pref.begin()) - 1;
        ans.push_back(k);                          // k 就是「最多能选几个」，可以为 0
    }
    return ans;
}
```

因为 `pref[0] = 0 <= q`（`q >= 0`），`upper_bound` 至少返回 `1`，所以 `k >= 0`，不用特判「一个都选不了」。这就是哨兵 `pref[0]` 的第二个好处——第一个好处是省掉「从头开始」的特判。

## 复杂度

- 排序 O(n log n)，前缀和 O(n)，每个查询 O(log n)：总计 O((n + q) log n)；空间 O(n)。

## 易错点

- **前缀和数组只有 `n` 个位置** → 「全选」的情况算不出来（我这次的 bug）。
- `pref[i + 1] = pref[i] + nums[i]` 里的下标错位：`pref` 比 `nums` 长一位，别写成 `pref[i] = pref[i-1] + nums[i]` 却忘了 `i=0` 的初值。
- 答案要的是**下标**还是**个数**：`upper_bound - begin() - 1` 得到的下标 `k` 恰好等于「个数」（因为 `pref` 下标就是元素个数），这题有巧合，别当成通用规律。
- 用 `lower_bound` 而不是 `upper_bound`：`lower_bound` 找第一个 `>= q`，减一得到的是「最后一个 `< q`」，`q` 恰好等于某个前缀和时会少选一个。
- 排序会打乱 `nums`，答案如果要求原下标就不能排——这题只要长度，所以没关系。
- 和用 `int` 一般够（本题 `1e5 * 1e3` 量级），但习惯上用 `long long` 不吃亏。

## 我的感想

这题和 2300 连起来看，是「**前缀和 + 二分**」这个组合的标准双人舞：

- 2300：排序 + 二分（不用前缀和）；
- 2389：排序 + 前缀和 + 二分（前缀和是二分的**被查对象**）。

共同点都是「**把一个 O(n) 的扫描换成 O(log n) 的查询**」，前提是「被查的东西有序」——2389 的有序是「排序后前缀和天然递增」，2300 的有序是「排完序的 potions」。

我原来以为前缀和就是「快速求区间和」，这题让我看到它的第二种用法：**把「选前 k 个的和」变成一个可以直接二分的单调数组**。这时候前缀和不是用来「减少计算」的，而是用来**制造单调性**的。

关于「子序列」还有个认识：**子序列 + 求和/计数 的题，先想能不能排序**。排序不改变「能选哪些元素」，只改变「选的方式」，而一旦有序，很多问题就退化成前缀/后缀。

## 更优解

可以离线做：把 `queries` 连同下标一起排序，然后双指针扫 `nums` 的前缀累加，O((n + q) log(n + q)) 但因为前缀和本身已递增，二分已经够快。更进一步的「值域桶」不适用（和的范围太大）。

如果 `queries` 里的值很大，注意 `upper_bound` 的比较对象类型要和容器元素一致（`long long`），别让隐式转换搞出歧义。
