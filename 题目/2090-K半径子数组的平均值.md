# 2090. K 半径子数组的平均值

## 题意

给数组 `nums` 和整数 `k`。对每个下标 `i`，取以 `i` 为中心、半径 `k` 的子数组 `nums[i-k .. i+k]`，求它的平均值（**向下取整**）。如果这个区间越界（`i-k < 0` 或 `i+k >= n`），该位置填 `-1`。

返回长度与 `nums` 相同的数组。

## 我的思路

定长滑动窗口，但和 1456 有两处不同，必须先想清楚：

1. **窗口长度不是 k，是 `2k+1`**。`k` 是半径，中心占一格。
2. **答案不是「窗口的某个值」，而是「写回中心下标」**。窗口 `[r-2k, r]` 的中心是 `r-k`，所以收答案时写 `ans[r-k]`，不是 `ans[r]`。

这两点想错，代码能跑但答案会整体错位。

## 代码

```cpp
class Solution {
public:
    vector<int> getAverages(vector<int>& nums, int k) {
        int n = (int)nums.size();
        int win = 2 * k + 1;                 // 真正的窗口长度
        vector<int> ans(n, -1);              // 默认全是 -1，越界的位置不用管
        long long sum = 0;
        for (int r = 0; r < n; ++r) {
            sum += nums[r];                          // 进
            if (r >= win) sum -= nums[r - win];      // 出
            if (r >= win - 1)                        // 窗口刚好 win 个
                ans[r - k] = (int)(sum / win);       // 写到中心 r - k
        }
        return ans;
    }
};
```

**复杂度**：时间 O(n)，空间 O(n)（返回值本身）。

## 为什么这么写就对了

- `vector<int> ans(n, -1)` 一步解决「越界填 -1」——只有窗口真正满的时候才覆盖，否则保持 -1。**不需要单独判断 `i-k < 0` 或 `i+k >= n`**，这是这题最省事的写法。
- 循环跑完时 `r` 从 `win-1` 到 `n-1`，对应的中心从 `k` 到 `n-1-k`，正好是所有合法中心，一个不多一个不少。
- `k == 0` 时 `win == 1`，每次 `r >= 0` 都成立，`ans[r] = nums[r]`，边界自然成立，不用特判。

## 易错点

- **窗口长度写成 `k`** 而不是 `2k+1`。这是本题最大的坑（半径 ≠ 长度）。
- 答案写回 `ans[r]` 而不是 `ans[r-k]`，结果整体右移 k 位。
- `sum` 用 `int`：`n` 最大 10^5、元素最大 10^5，和能到 10^10，**必溢出**。用 `long long`。
- 平均值「向下取整」：整数除法 `sum / win` 本身就是向下取整（对非负数是），别写成四舍五入。
- 用 `(sum + win/2) / win` 想着「更准」——题目要的就是向下取整，加了就错。
- 忘了 `k` 可能大于 `n/2`，此时整个 `ans` 全是 `-1`，循环里 `r >= win-1` 一次都不成立，逻辑天然正确，但要确认它确实不崩。

## 我的感想

「半径」这种说法会骗人——`k` 是半径，但窗口有 `2k+1` 个元素。**凡是题目用「半径」「范围」「距离」描述窗口，先换算成真正的长度再套模板**。

另一个收获是 `vector<int> ans(n, -1)` 这个默认值技巧：与其在循环里判越界，不如让默认值承担「不合法」的语义，代码短且不容易漏。
