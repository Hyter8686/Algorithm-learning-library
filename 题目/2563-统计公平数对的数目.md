## 题意

给数组 `nums` 和两个整数 `lower`、`upper`，数有多少个下标对 `i < j` 满足

```
lower <= nums[i] + nums[j] <= upper
```

## 我的思路

水到渠成。就是「两数之和的计数版」：

1. 排序（下标对不要求顺序，排序不改变答案）；
2. 固定 `i`，那么 `j` 必须落在 `[lower - nums[i], upper - nums[i]]` 这个值域里；
3. 有序数组上数「值落在某区间的元素个数」= `upper_bound` − `lower_bound`。

把每个 `i` 的答案累加就是结果。

## 做法

排序后对每个 `i`，在 `nums[i+1 .. n-1]` 里二分：

```cpp
auto hi = upper_bound(nums.begin() + i + 1, nums.end(), upper - nums[i]);
auto lo = lower_bound(nums.begin() + i + 1, nums.end(), lower - nums[i]);
ans += hi - lo;                     // ans 必须是 long long
```

**复杂度**：O(n log n) 时间，O(1) 额外空间（排序本身 O(log n) 栈）。

也可以双指针做到 O(n log n) 排序 + O(n) 扫描，本质一样。

## 易错点

- **答案要用 `long long`**。n = 10^5 时最多 `C(n,2) ≈ 5×10^9`，`int` 装不下（21 亿就爆）。这是我这题真正的错因——**没算上界就选了类型**。
- **多余的特判全都删掉**。我一开始为「`i` 和 `j` 会不会重合」「`lower` 可能是负数」加了分支，结果反而在某些用例上错。通用的 `lower_bound(i+1, ...)` 已经把「不重合」编码进去了，`lower - nums[i]` 是负数时二分也照样正确（`lower_bound` 对越界值返回 `begin`）。
- 二分的区间要从 `i + 1` 开始，从 `0` 开始会把 `(i,j)` 和 `(j,i)` 数两遍，还会把自己和自己配上。
- `upper - nums[i]` 可能溢出 `int`（若 `upper` 接近 `1e9` 且 `nums[i]` 为负），稳妥起见用 `long long` 算阈值。

## 我的感想

这题思路一分钟就出来了，**两次失败都在「想当然」**：

1. 数量级没算。看到「数对个数」就写 `int`，是习惯问题——以后凡是**答案可能是 O(n²) 规模的计数**，先心算一下上界（`n=1e5` → 5×10^9），再决定类型。这条可以推广成：**写变量之前先问「它的上界是几」**。
2. 特判上瘾。加特判的心理是「这个情况我不敢保证通用逻辑能处理」，但**每加一个特判就多一条独立分支要验证**，而通用逻辑往往是自洽的。删掉特判就好了，说明它们全是自己吓自己。

所以判断「该不该加特判」有个简单的标准：**能不能说出一个具体的、会失败的反例？** 说不出就先别加，写完跑一遍再补。凭感觉加的特判，比不加更容易错。
