## 题意

设计一个「可快照」的数组：

- `SnapshotArray(length)`：长度 `length` 的数组，初始全 0；
- `set(index, val)`：把 `index` 改成 `val`；
- `snap()`：拍快照，返回快照编号 `snap_id`（从 0 开始，每次调用 +1）；
- `get(index, snap_id)`：返回第 `snap_id` 次快照那一瞬间的 `a[index]`。

## 我的思路

**第一反应（错）**：每次 `snap()` 把整个数组拷一份存下来。

```
snapshots: vector<vector<int>>
```

`snap()` 是 O(n)，n 次快照就是 O(n × 快照数)，快照数可达 5×10^4，n 可达 5×10^4 → 2.5×10^9 个 int。**内存直接超限**。

**第二次（对了一半）**：意识到「每次快照只有极少数位置变了」，于是想「每个版本记录一下哪些位置被改过」——但没想清楚具体该存什么。

**第三次（题解确认思路一致）**：**每个下标各自记一本「修改历史」**：

```
a[0] 的历史: (0, 5) (3, 7) (7, 2)     // (生效的快照编号, 值)
a[1] 的历史: (0, 0)
...
```

- `set(index, val)`：往 `history[index]` 尾部追加 `(当前快照数, val)`；
- `get(index, snap_id)`：在 `history[index]` 里找**最后一个快照编号 ≤ snap_id** 的条目，它的值就是答案。

关键在最后一句：`snap_id` 时刻的值 = 「不晚于这次快照的最后一次修改」的结果。这和 2080 的「值 → 位置列表 + 二分」是**同一个骨架**：一个维度当键、另一个维度存有序列表、查询靠二分定位。

## 做法（关键一步）

每个下标维护一个 `vector<pair<int,int>>`（快照号, 值）。查询时在 pair 数组上二分。

**问题：pair 能二分吗？** 能。`std::pair` 有 `operator<`，而且是**字典序**比较（先比 `first`，相等再比 `second`）。所以普通的 `upper_bound` / `lower_bound` 直接就能用在 `vector<pair<int,int>>` 上。

要找「最后一个 `first <= snap_id`」的条目，用探针 `(snap_id, INT_MAX)`：

```cpp
auto it = upper_bound(h.begin(), h.end(), pair<int,int>{snap_id, INT_MAX});
// it 指向第一个 first > snap_id 的条目，它的前一个就是答案
return (it == h.begin()) ? 0 : prev(it)->second;
```

**复杂度**：`set` O(1) 摊还（追加），`snap` O(1)，`get` O(log 修改次数)。总空间 O(总修改次数)，与快照数量无关。

## 易错点

- **别按快照存整个数组**，这是本题唯一的坑。快照多、修改少 → 存修改；修改多、快照少 → 存快照。看哪个维度稀疏。
- `pair` 的 `<` 是字典序，所以 `upper_bound` 的探针第二维要给一个**不小于所有可能值**的数（`INT_MAX`），否则相等的 `first` 会被误判。
- 每个下标的历史里**必须有一条 `snap_id = 0` 的初始记录**（值 0），否则「从没被改过」的查询会取到 `begin()` 之前，要额外判断。我的写法是在构造函数里 `resize(length, {{0, 0}})` 一次搞定。
- `set` 里记录的「当前快照数」是 `snap()` 被调用的**次数**，不是 `snap_id + 1`——两者相等，但想清楚这一点才不会差一位。
- 想用 `upper_bound` 却传了 `lower_bound` 会少取一条记录（和 2080 里「`upper_bound` 不能换 `lower_bound`」是同一个错误）。

## 我的感想

这题一开始「看着眼熟」，其实是因为它和 2080 是**同构的**：

| | 2080 | 1146 |
| --- | --- | --- |
| 谁当键 | 值 `v` | 下标 `index` |
| 存什么 | 出现过哪些位置 | 有哪些 (快照号, 值) |
| 查询 | `upper_bound(right) − lower_bound(left)` | 找最后一个 `first ≤ snap_id` |
| 二分对象 | 有序 `int` 数组 | 有序 `pair` 数组 |

所以真正的门槛不是「想到历史记录」——我第二次就想到了——而是**「一对数据怎么当成有序的东西二分」**。答案是：`pair` 天生有序（字典序），根本不用自己写比较函数。我之前以为二分只能用在 `int` 数组上，这是把「技巧」当成了「限制」。

另外一个收获是内存意识的觉醒：**存「每次操作的增量」而不是「每次操作的完整状态」**，几乎是所有「版本号 / 时间点查询」类问题的通用解法（git 的 commit、数据库的 WAL 都是这个思路）。看到「历史某个时刻的值」，第一反应应该是「**我只需要知道那时候最后一次改动是什么**」。
