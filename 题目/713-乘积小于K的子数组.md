## 题意

给一个正整数数组 `nums` 和整数 `k`，返回**乘积小于 k** 的连续子数组个数。

```
输入: nums = [10,5,2,6], k = 100
输出: 8
解释: 8 个子数组乘积 < 100：[10] [5] [2] [6] [10,5] [5,2] [2,6] [5,2,6]
```

注意 `[10,5,2] = 100` 不满足（要求严格小于）。

## 我的思路

和 209 是一对：**209 求最短，这题求和最短无关，求「有多少个」**。窗口还是那个窗口——所有元素都是正数，乘积随窗口扩大而单调不减，所以「乘积 < k」对收缩封闭，能滑。

一开始我卡在「怎么数」上：窗口 `[l, r]` 合法，那以 `r` 结尾的合法子数组有哪些？答案是 `[l,r]`、`[l+1,r]`、…、`[r,r]`，一共 `r - l + 1` 个——因为起点越往右窗口越小，乘积只会更小，一定也合法。

所以数法就是每处理一个 `r`，把 `r - l + 1` 累加到答案上。

## 解法

```cpp
int numSubarrayProductLessThanK(vector<int>& nums, int k) {
    if (k <= 1) return 0;               // 元素都 ≥ 1，乘积最小是 1，不可能 < k
    int n = (int)nums.size();
    long long prod = 1;                 // 防溢出：prod 最坏 ≈ k * 1000
    int l = 0, ans = 0;

    for (int r = 0; r < n; ++r) {
        prod *= nums[r];
        while (prod >= k) prod /= nums[l++];   // 缩到合法为止
        ans += r - l + 1;                       // 以 r 结尾的合法子数组个数
    }
    return ans;
}
```

`k <= 1` 那句不是可选的：`k = 0` 或 `k = 1` 时窗口永远不合法，`while` 会把 `l` 推到 `r + 1`，然后 `r - l + 1` 变成 0 或负数——虽然是 0 但 `l` 会越界。直接特判更省心。

## 复杂度

- 时间 O(n)：`r` 走 n 步，`l` 总共也只走 n 步。
- 空间 O(1)。

## 易错点

- **`ans += r - l + 1` 里的 `l` 必须是收缩完之后的 `l`**，写在 `while` 前面就错了。
- `k <= 1` 不特判 → `l` 越界。
- `prod` 用 `int`：`prod < k ≤ 1000 × 1000` 一般安全，但 `nums[i]` 到 1000、`k` 到 10^6 时，`prod` 在乘完新元素、还没收缩的那一瞬间可以到 10^9 量级，用 `long long` 一劳永逸。
- 是「乘积」不是「和」，所以不能像 209 那样直接前缀和；除法回退要求元素非零且是整数（这题元素 ≥ 1，成立）。

## 我的感想

这题真正教的是**滑窗的两种用途**：

- 求最长 / 最短 → 维护一个「最优窗口」，答案是窗口长度；
- 求**个数** → 每一步累加「以 `r` 结尾的合法子数组个数」= 窗口长度。

第二种是第一种的对偶：第一种问「最长的那个窗口多长」，第二种问「所有窗口长度加起来是多少」。想通这点以后，`ans += r - l + 1` 就不用背了——它就是「以 r 结尾有几种起点」。

另外这题是个很好的「计数型滑窗」模板：只要「固定右端点、合法左端点是一段连续区间」，个数就是区间长度。以后遇到「和小于 k 的子数组个数」是同一份代码。

## 更优解

O(n) 已经是最优。另一种写法是「对每个 `l` 算最远能到哪」，本质相同。

顺带一提：如果问的是「乘积**等于** k 的个数」，滑窗就不够了（乘积不单调、要精确），得用前缀积 + 哈希并处理除零。
