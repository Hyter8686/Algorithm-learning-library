## 题意

两组数 `spells`、`potions`，乘积 `spells[i] * potions[j] >= success` 算一对（有序对，i 在前 j 在后）。对每个 `spells[i]`，问它能和多少瓶药水配对成功。

```
输入: spells = [5,1,3], potions = [1,2,3,4,5], success = 7
输出: [4,0,3]
解释: i=0 时 5*2,5*3,5*4,5*5 ≥ 7 → 4 个；i=1 时 1*5=5 < 7 → 0 个
```

`spells[i], potions[j] <= 10^5`，`success <= 10^10` → **乘积会超 int，必须 `long long`**。

## 我的思路

固定 `spells[i]`，需要 `potions[j] >= success / spells[i]`。所以：

1. 先把 `potions` 排序（一次性，之后每次查询 O(log m)）；
2. 对每个 `spells[i]` 算出阈值 `need = ceil(success / spells[i])`；
3. 在 `potions` 里二分找第一个 `>= need` 的位置 `idx`，能配对的瓶数就是 `m - idx`。

我一开始写的是「二分乘出来的乘积」，也就是拿 `potions[mid] * spells[i] >= success` 当判定条件——能过，但每个 `mid` 都要做一次乘法，还得小心乘法溢出。改成**先算阈值、再比大小**以后，二分内部只有整数比较，干净很多。

## 核心技巧：上取整

`ceil(success / s)` 不能用浮点（精度 + 慢），整数写法：

```cpp
long long need = (success + s - 1) / s;      // 上取整，(a + b - 1) / b
```

**为什么成立**：设 `success = q*s + r`（`0 <= r < s`）。

- `r == 0`：`(q*s + s - 1)/s = q + (s-1)/s = q`，正好是 `ceil`；
- `r > 0`：`(q*s + r + s - 1)/s = q + (r+s-1)/s = q + 1`，也是 `ceil`。

统一写成 `(a + b - 1) / b` 就行，不用分情况。等价写法 `a / b + (a % b != 0)`——就是我说的「用 `?:` 判断是否有余」，也对，但多一次除法，而且 `(a+b-1)/b` 更像一个「公式」而不是一段逻辑。

⚠️ 只对 **a ≥ 0、b > 0** 成立。C++ 整数除法向零截断，负数上取整会算错（`(-5 + 2)/(-2)` 不等于 `ceil(-2.5)`）。

## 解法

```cpp
vector<int> successfulPairs(vector<int>& spells, vector<int>& potions, long long success) {
    sort(potions.begin(), potions.end());
    int m = (int)potions.size();
    vector<int> ans;
    ans.reserve(spells.size());

    for (int s : spells) {
        long long need = (success + s - 1) / s;                    // 上取整
        int idx = (int)(lower_bound(potions.begin(), potions.end(), need)
                        - potions.begin());                         // 迭代器相减 → 下标
        ans.push_back(m - idx);                                     // 从 idx 到末尾全都能配
    }
    return ans;
}
```

`need` 用 `long long`：`success` 到 10^10，加 `s - 1` 之后肯定超 int。

## 复杂度

- 排序 O(m log m)，每个 spell 一次二分 O(log m)，总计 O(m log m + n log m)；空间 O(1) 额外（不计答案）。

## 易错点

- **`lower_bound` 返回的是迭代器，不是地址**。`cout << it` 打印不出来；要下标就 `it - potions.begin()`。
- **迭代器相减本身就得距离**，再 `/ sizeof(int)` 是纯错——`sizeof` 是编译期字节大小，和「隔了几个元素」毫无关系。这是 C 指针思维带来的误会：`int*` 相减确实是「元素个数」，那已经是除了 `sizeof` 的结果；迭代器是同一套语义，`it2 - it1` 直接就是元素个数（`ptrdiff_t` 类型）。
- `m - idx` 而不是 `idx`——问的是「有多少个能配对」，`idx` 是第一个能配的位置，右边全都能配。
- 乘出来再比 → 溢出。要么先除（上取整），要么 `(long long)potions[mid] * s`。
- `(success + s - 1)` 用 int 溢出。
- `potions` 排序要在循环外做一次，别在循环里排。

## 我的感想

这题表面是二分，实际教的是「**把比较挪到二分外面**」：

- 比较式里有乘法 → 除法把阈值算出来，二分化成「找第一个 ≥ need」；
- 比较式里有浮点 → 乘到整数域（和 1343 的「平均值乘过去」是同一招）；
- 比较式里有两个变量 → 固定一个，把另一个算成常量。

二分内部越「纯」（只有一次整数比较），越不容易错、越快。

另外这题让我真正分清了**迭代器**和**指针**。语法书里说「迭代器像指针」，我就以为它们是一回事，结果：

| 想做的事 | 正确写法 | 错误写法 |
| --- | --- | --- |
| 迭代器 → 下标 | `it - v.begin()` | `it / sizeof(int)`、`(int)it` |
| 两个迭代器的距离 | `it2 - it1`（随机访问容器 O(1)） | `(it2 - it1) / sizeof(int)` |
| 取元素 | `*it` 或 `v[it - v.begin()]` | `*it` 当数组用 |

「像指针」指的是**用法相似**（能 `*`、能 `++`、能相减），不是「内存地址相同」。`vector` 的迭代器在实现上确实常是裸指针包装，但 `set`/`map` 的迭代器是树节点指针，`sizeof` 那套更是完全没意义。

## 更优解

O(n log m + m log m) 已是标准解。

也可以**对 spells 排序后再双指针**：`spells` 升序时，需要的阈值 `need` 单调递减，对应的 `idx` 也单调递减，于是 O(n log n + m) 内层线性。但要注意答案要按原顺序输出（排序前存下标），代码复杂度上升，这题数据量用二分足够。

还有一个思路：对 `potions` 也做前缀/后缀计数（值域 10^5，桶计数 + 后缀和），查询 O(1)。属于「值域小就上桶」的套路，和二分是两条路。
