## 题意

设计一个数据结构，支持：

- `RangeFreqQuery(arr)`：用数组初始化；
- `query(left, right, value)`：返回 `arr[left..right]`（含端点）里 `value` 出现的**次数**。

```
arr = [12, 33, 4, 56, 22, 2, 34, 33, 22, 12, 34, 56]
query(1, 2, 4)  → 1
query(0, 11, 33) → 2
```

数据范围：`arr.length <= 10^5`，`arr[i] <= 10^4`，查询次数 `<= 10^4`。

## 我的两次尝试（都失败）

**第一次：暴力。** 每次 query 扫一遍 `arr[left..right]` 数 `value`。

- 复杂度 O(n) 一次，10^4 × 10^5 = 10^9 → 超时。
- 问题在于**没有任何预处理**，每次查询都从零开始。

**第二次：前缀频率。** 想「用前缀和的思想，记下每个位置之前每个数字出现的次数」，写成

```cpp
vector<unordered_map<int,int>> cord(10001);   // 错得比较彻底
```

然后每个 query 用 `cord[right][value] - cord[left-1][value]` 相减。写完就报错，也调不下去。

复盘一下这段代码为什么必然不行：

1. **空间爆炸**。`cord[i]` 要存「前 i 个元素里每个值的出现次数」，最坏有 10^5 个不同的值，总空间 O(n × 不同值个数) = 10^10 级别。这是**信息量本身太大**，不是常数优化能救的。
2. **`10001` 这个大小是错位的**。它看起来像是「值域大小」（`arr[i] <= 10^4`），但 `cord` 的第一维下标是**位置**（0..10^5），按值域开就装不下。我把「两种不同的 10000」混成了一个。
3. 就算空间够，建表本身是 O(n × 值域) 或 O(n²) 的，也过不了。
4. `query` 里访问 `cord[left-1]` 时 `left == 0` 还要特判，前缀和的经典边界问题。

**第三次：看题解。** 正解是「**按值建索引**」而不是「按位置建索引」。

## 正解的思维转换

我的失败版思路是：**位置 → 每个值出现了几次**（前缀频率表）。这条路的信息量是 O(n × d)，做不下去。

题解的思路是：**值 → 它出现过的所有位置**（有序列表）。

```
arr  = [12, 33, 4, 56, 22, 2, 34, 33, 22, 12, 34, 56]
12   → [0, 9]
33   → [1, 7]
34   → [6, 10]
56   → [3, 11]
```

于是 `query(left, right, value)` 变成：在 `pos[value]` 这个**升序数组**里，数有多少个元素落在 `[left, right]` 里。这是标准的「有序数组上数区间内元素个数」：

```
upper_bound(pos[value], right) - lower_bound(pos[value], left)
```

- 预处理 O(n)：扫一遍，边扫边把下标塞进对应值的列表（天然有序，因为是从左到右扫的）。
- 每次查询 O(log n)。
- 总空间 O(n)：每个下标恰好出现一次。

**为什么这个视角能把空间从 O(n·d) 降到 O(n)**：因为「位置」不是随元素无限膨胀的维度——**一个元素只属于一个值**。按位置建表要复制「所有值」的信息，按值建表只记录「自己出现过的位置」。

## 解法

因为 `arr[i] <= 10^4`，值域小，直接用数组代替 `unordered_map` 更快：

```cpp
class RangeFreqQuery {
    vector<vector<int>> pos;
public:
    RangeFreqQuery(vector<int>& arr) {
        pos.resize(10001);                       // 按值域开（arr[i] <= 10^4）
        for (int i = 0; i < (int)arr.size(); ++i)
            pos[arr[i]].push_back(i);            // 从左到右扫 → 每个列表天然升序
    }

    int query(int left, int right, int value) {
        const vector<int>& p = pos[value];
        auto hi = upper_bound(p.begin(), p.end(), right);   // 第一个 > right
        auto lo = lower_bound(p.begin(), p.end(), left);    // 第一个 >= left
        return (int)(hi - lo);                              // 落在 [left, right] 的个数
    }
};
```

值域不大的话，`vector<vector<int>>` 比 `unordered_map<int, vector<int>>` 好：没有哈希开销、没有 rehash、缓存友好。

## 复杂度

- 构造：O(n) 时间，O(n) 空间（每个下标存一次）。
- 查询：O(log k)，k 是该值出现次数。
- 总计：O(n + q log n)。

## 易错点

- **把「位置域」和「值域」搞混**：`pos` 的第一维是按**值**开的，所以大小是值域（10001）；我错的那版是按位置开的，大小应该是 n+1。
- `upper_bound(right) - lower_bound(left)` 两边的开闭不能都写 `lower_bound`：`lower_bound(right)` 会把 `left..right` 里恰好等于 `right` 的那些漏掉一位。
- 用 `hi - lo` 得到的是 `ptrdiff_t`，返回 `int` 要强转。
- `value` 可能从来没出现过 → `pos[value]` 是空数组，`hi == lo == begin()`，返回 0，**不用特判**（这是空容器上二分的天然行为）。
- 用 `unordered_map` 版本时，`query` 里别用 `pos[value]` 直接访问（会插入新键，虽然不影响答案，但会无谓扩容）；用 `find` 或者一开始就 `vector<vector<int>>`。
- 如果 `value` 超出值域上界，数组版会越界，要么按题目范围开够，要么用哈希版。

## 我的感想

这题的价值不在代码（就六行），而在**那一次视角的转置**：

| | 我的思路 | 正解 |
| --- | --- | --- |
| 索引的键 | 位置 `i` | 值 `v` |
| 存的内容 | 每个值出现几次 | 它出现在哪些位置 |
| 空间 | O(n × d) | O(n) |
| 查询 | O(1) 但建不起表 | O(log k) |

我一直在想「怎么把前缀和搬到二维」，题解想的是「**这个问题本来就不该按位置组织**」。

一个更有用的问法：**这道题的「实体」是什么？** 这里实体是「元素的一次出现」，它有两个属性——值、位置。我按位置分组，题解按值分组。**分组方式的选择，直接决定能不能压缩空间**。当某个维度是「每个元素各占一个」的时候（这里的位置和值都是），按哪边分组都只有 O(n) 条数据；但要按位置分组还得存「所有值」，就必须复制信息了。

另一个收获是关于「存在性 vs 计数」：`query` 只要「有没有」，理论上可以提前返回，但用 `hi - lo` 直接算个数反而更简单——**能算个数的时候，别为「只要存在」写特判**。

还有一个很实用的判断：**「数组不变 + 区间内某值的出现次数」是倒排索引的标准场景**。以后看到「区间内查询某个值」就该条件反射想到 `值 → 有序位置列表 + 二分`。

## 更优解

- **离线**：如果所有 query 预先给出，可以按 `left` 排序 + 树状数组做，O((n + q) log n)，常数更小但没有必要。
- **可持久化线段树 / 主席树**：支持「区间第 k 小」「区间内 ≤ x 的个数」这类更一般的问题，O(log V) 查询，代价是 O(n log V) 空间。这题不需要——问题比它简单得多。
- **值域前缀和**：对每个值做一次前缀和，空间 O(d × V) 或 O(n) 稀疏版，本质上和位置列表等价。
- **如果要支持修改**（本题不支持）：`vector<set<int>>` 或树套树，复杂度上一个台阶。
