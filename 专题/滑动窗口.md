# 滑动窗口

## 什么时候想到它（识别信号）

三个条件同时出现时，基本就是它：

1. 找的是**连续子数组 / 连续子串**（不是子序列）；
2. 要**最长 / 最短 / 是否存在 / 有几个**；
3. 窗口扩大时某个指标**单调**（和只增不减、不同字符数只增不减）。

如果数组里有负数又要求「和 ≥ k 的最短」，单调性被破坏，滑窗失效 → 换前缀和 + 单调队列/二分。

## 核心思想

用 `[l, r]` 框住一段连续区间，`r` 只往右扩、`l` 只往右收。
因为 `l` 不回退，每个元素最多进出窗口各一次 → **O(n)**。

难点不在模板，在**「窗口里维护什么状态」**和**「什么时候收缩」**。

## 模板

### 可变长 · 求最长

```cpp
int l = 0, ans = 0;
for (int r = 0; r < n; ++r) {
    add(a[r]);                      // 1. 右端进窗，更新状态
    while (invalid()) {             // 2. 只要不合法就一直收
        remove(a[l]);
        ++l;
    }
    ans = max(ans, r - l + 1);      // 3. 合法时更新答案
}
```

### 可变长 · 求最短

```cpp
int l = 0, ans = INT_MAX;
for (int r = 0; r < n; ++r) {
    add(a[r]);
    while (valid()) {               // 注意：合法时也要继续收，试试更短
        ans = min(ans, r - l + 1);  // 答案在收缩循环内部更新
        remove(a[l]);
        ++l;
    }
}
```

**两个模板的唯一区别**：最长在「不合法」时收，最短在「合法」时收，且答案更新位置不同。把这两个记反是最常见的 bug。

### 定长窗口（窗口长度恒为 k）

**最稳的写法：一个循环搞完**

```cpp
int cnt = 0, ans = 0;
for (int r = 0; r < n; ++r) {
    add(a[r]);                        // 1. 右端无条件进
    if (r >= k) remove(a[r - k]);     // 2. 窗口超过 k 个，左端出
    if (r >= k - 1) ans = max(ans, cnt);  // 3. 窗口恰好 k 个，收答案
}
```

三段判断条件都直接由 `r` 和 `k` 算出来，**不依赖「上一个循环留下了什么」**，所以边界不会错。

**两个循环的写法（也能用，但要小心下标）**

```cpp
int cur = accumulate(a.begin(), a.begin() + k, 0);   // [0, k-1]
int ans = cur;
for (int r = k; r < n; ++r) {       // r 从 k 开始，第一格进的就是 a[k]
    cur += a[r] - a[r - k];
    ans = max(ans, cur);
}
```

这里的陷阱是：如果用 `for (int r = 0; r < k; ++r)` 做初始化，循环结束时 `r` **已经等于 k**，而 `a[k]` 正是下一个该进窗口的元素。此时再写 `++r` 就跳过 `a[k]`，并且**从此 r 永远偏大一格，「进」和「出」不再对应同一个窗口，后面全错**。（我在 [1456. 定长子串中元音的最大数目](../题目/1456-定长子串中元音的最大数目.md) 上就是这么错的。）

一句话：**下标变量的语义要唯一**。「窗口右端」和「下一个待处理元素」不是一回事，别共用一个变量；实在要复用，初始化循环就换个名字 `i`。

定长窗口和可变长窗口的本质区别：**定长窗口不需要 `while` 收缩，一出就进，长度恒定**；滑一次的数据变化只由「尾部进的那个」和「头部出的那个」决定。

### 「定长」是必要不充分条件

题目要求「长度恰好为 k 的子数组」→ 可以**考虑**定长窗口；但能不能真的 O(1) 滑动，取决于**窗口里要维护的那个量能不能靠「进一个、出一个」增量更新**。做题时问三句：

1. **维护的是「和」「计数」吗？** → 能，一个变量搞定（1456 元音数、1343 窗口和、2090 窗口和、2379 白块数、643 窗口和）。
2. **要的是「窗口内元素的最大值 / 最小值」吗？** → 不能直接维护，最大值出窗后无法回退。换**单调队列**（239）。
3. **要的是「中位数 / 第 k 大 / 需要排序」吗？** → 换 `multiset` 或对顶堆（480）。

一个容易混淆的点：**「窗口内计数的最值」和「窗口内元素的最值」是两回事**。

- 2379 求「窗口里 `'W'` 个数的最小值」：`'W'` 个数是可增删的计数 → 能滑。
- 239 求「窗口里元素的最大值」：元素删了就回不去 → 必须单调队列。

判断时盯着**你维护的那个变量是什么**，而不是盯题目问什么。这也是定长窗口题真正的「数据处理环节」：题目问的和你要维护的，往往不是同一个量（1343 问平均值、维护和；2379 问涂色次数、维护白块数）。

### 两段式：答案 = 固定部分 + 窗口增量

定长窗口题的另一大来源是「选一个长度为 k 的区间去施加某种影响」。这类题的答案往往能拆成两段：

```
答案 = 与区间无关的固定部分（一遍 for 累加）
     + 区间内能带来的增量（定长窗口求最值）
```

典型是 [1052. 爱生气的书店老板](../题目/1052-爱生气的书店老板.md)：总满意人数 = **本来就满意的人**（`grumpy[i] == 0`，与老板选哪段无关，固定）+ **窗口内被「救」回来的人**（`grumpy[i] == 1` 的 `customers[i]`，长度 `minutes` 的窗口求最大和）。

**拆的前提**：影响是「局部且可加」的——老板这 `minutes` 分钟不生气，只改变这一段里的人，别处不受影响。如果影响会外溢（顾客改天再来之类），就不能拆。

**为什么值得拆**：不拆就会写出「每个窗口重新模拟一遍影响」的版本，复杂度 O(n²)。1052 的 n 是 2×10^4，O(n²) 是 4×10^8，正好卡在超时边上（我在 78 个用例里挂了 2 个）。拆开之后两段都是 O(n)。

**识别信号**：题目里出现「可以选一段」「有一次机会」「可以改变连续 k 个」→ 先问自己「不改的那部分是不是能单独算出来」。

### 窗口里可以同时维护多个量

模板不是「一个窗口只能有一个变量」。2841 要同时维护 `sum`（窗口和）和 `cnt`（值 → 次数，取 `size()` 得不同元素个数），两个量都是 O(1) 增删，所以照样能滑：

```cpp
sum += nums[r]; ++cnt[nums[r]];
if (r >= k) { sum -= nums[r-k]; if (--cnt[nums[r-k]] == 0) cnt.erase(nums[r-k]); }
if (r >= k - 1 && (int)cnt.size() >= m) ans = max(ans, sum);
```

判断「能不能滑」的标准始终是**每个要维护的量单独能不能 O(1) 增删**，不是「量的个数」。

## 为什么不定长窗口一定能得出最优解

直觉版：**`r` 枚举所有可能的「窗口右端」，`l` 在 `r` 固定时去找最好的左端**。求最长时窗口越大越不可能满足条件，一旦不合法就往右挪 `l` 缩到「刚好合法」；求最短时反过来，只要还合法就继续缩。

要把直觉变成「保证」，得证明三件事。

### ① 每个 `r` 只需要一个 `l`（代表元足够）

先要求约束**对收缩封闭**：整段合法 ⇒ 它的每一段子数组也合法。等价说法是「窗口只扩大时，合法性只会单向变化」。

- **求最长**（如「至多 k 个不同字符」）：窗口越小越容易合法。固定 `r` 时合法左端是 `l ≥ F(r)` 的一段，取**最小**的合法 `l` 就最长。
- **求最短**（如「和 ≥ target」）：窗口越大越容易合法。固定 `r` 时合法左端是 `l ≤ L(r)` 的一段，取**最大**的合法 `l` 就最短。

也就是 `O(n²)` 个窗口里，每个 `r` 只有一个值得看。这是降到线性的第一步。

### ② 那个「最好的 `l`」只往右走

- **最长**：若 `[l, r]` 已经不合法，`[l, r+1]` 更大、只会更不合法 → 下一轮需要的 `l` 不会变小。
- **最短**：这里要留神，`L(r)` 是**可能变小**的——新进来的元素可能让更早的起点也变合法。但**跳过的窗口不会更优**：若某个窗口 `[l', r+1]`（`l' < l`）合法，那么上一步的 `[l-1, r]` 必然也合法，且更短（长度只差 2）。既然更短的已经被记过，`l` 就不必回退。

两种情形下 `l` 都只增不减——这就是「一次扫描」的全部秘密。

### ③ 复杂度是摊还 O(n)

`r` 走 `n` 步，`l` 总共最多走 `n` 步；每个下标**进窗口一次、出窗口一次**，`while` 里的操作摊还 O(1)，总计 O(n)。

### 判据：一句话自查

> **窗口变大时，合法性是不是单向变化（只会变好，或只会变坏）？**

是 → 可以滑窗；不是 → 换别的。三个反例：

| 场景 | 为什么不行 | 正确做法 |
| --- | --- | --- |
| 「恰好 k 个不同整数」 | 「恰好」这个条件在两侧都不满足，不单调 | 用「至多 k」−「至多 k−1」作差（[992](https://leetcode.cn/problems/subarrays-with-k-different-integers/)） |
| 「和 ≥ target」但数组含负数 | 加负数会让和变小，`sum` 不随窗口扩大而单调 | 前缀和 + 单调队列（[862](https://leetcode.cn/problems/shortest-subarray-with-sum-at-least-k/)） |
| 要窗口内**元素**的最大值 / 中位数 | 合法性可判，但元素出窗后无法回退 | 单调队列（[239](https://leetcode.cn/problems/sliding-window-maximum/)）/ `multiset`、对顶堆（[480](https://leetcode.cn/problems/sliding-window-median/)） |

## 窗口内状态怎么维护

| 题型 | 窗口里存什么 |
| --- | --- |
| 无重复最长子串 | `unordered_map<char,int> last`（字符 → 最后出现位置，可以直接跳 `l`）或 `int cnt[128]` |
| 最小覆盖子串 | `need[c]` 还差几个 + `missing` 计数（差的总字符数），`missing == 0` 即合法 |
| 至多 k 个不同字符 | `unordered_map<char,int>` + `size()` |
| 和 / 乘积 | 一个变量（乘积要用 `long long`） |
| 求「有多少个」合法子数组 | 不存，直接 `ans += r - l + 1`（以 r 结尾的合法起点个数） |

字符类题优先用 **`int cnt[128]` 定长数组**：比 `unordered_map` 快一个数量级，还不用考虑迭代器失效。

## 易错点

- `while` 写成 `if`：不合法时可能一次收缩不够（尤其计数类）。
- 求最短时答案写在 `while` 外面 → 拿到的是「收缩前」的长度。
- 用 `map` 记字符次数时，计数减到 0 **必须 `erase`**，否则 `size()` 不等于「不同字符个数」。
- **边遍历边 `erase` 当前迭代器**是最典型的 UB：`for (auto &p : mp) mp.erase(p.first);` 会崩，要写 `it = mp.erase(it)`。
- `cnt[c]--` 后忘了判断是否需要 `erase`，`size()` 判据失效。
- 乘积类窗口初始值取 `1` 而不是 `0`，且别忘了 `long long`。
- **跨循环复用下标**：初始化窗口的循环写 `for (int r = 0; r < k; ++r)` 后，`r == k` 已经是下一个待处理位置，再 `++r` 就跳了一个元素，而且错位会一直延续下去（定长窗口的头号 bug）。
- 定长窗口「进」「出」「收答案」三步的顺序：只要收答案时进出都已完成就行，但别把 `ans = max(...)` 夹在进出之间，否则拿到的是长度 k±1 的窗口。
- `k == n` 时滑动循环一次都不执行，答案必须来自初始化的那一步。
- **求最小却把 `ans` 初始化成 `0`**：`min(0, 正数)` 恒为 0。求最小用 `INT_MAX`，求最大用 `0` / `INT_MIN`。
- **窗口长度换算错**：题目说「半径 k」「范围 k」时，真实长度可能是 `2k+1`（2090），先换算再套模板。
- **答案写回的位置错**：窗口 `[l, r]` 的答案不一定是 `ans[r]`，2090 要写回中心 `ans[r-k]`。
- **平均值直接除**：能乘过去就乘过去（`sum >= k * threshold`，1343），避开浮点误差。
- 窗口和用 `int` 累加溢出（2090：10^5 个 10^5 相加是 10^10；2841：10^14）。
- **窗口内又套一层循环 / `while` 向两侧扩**：等于放弃滑窗的增量优势，退化成 O(n²)。出现这种写法，先停下来问「是不是该把答案拆成固定部分 + 窗口增量」（1052 的教训）。
- **定长窗口里维护多个量时，忘了同步进出**：2841 的 `sum` 和 `cnt` 必须在同一处一起加、一起减，漏一个就错位。
- **求最长可以把 `while` 换成 `if`**（窗口长度只持平或 +1，合法窗口留冗余不影响最长解）；**求最短绝对不能**，那会漏掉更短的解（1004 vs 209 的差别）。
- **题目要求「必须」做一次操作时，答案要减一**：1493 必须删掉一个元素，所以窗口长度是 `r - l + 1 - 1`；全 1 数组的答案是 `n - 1` 而不是 `n`。
- **「出窗」不能无脑减**：当维护的量不是「和」而是「去重和」这类时，要看计数是否归零（3795：`if (--cnt[x] == 0) sum -= x;`，否则重复元素被减多次）。
