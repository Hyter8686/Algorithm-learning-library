# 二分查找

## 什么时候想到它（识别信号）

- 数组**有序**（或局部有序、旋转有序），要求在 O(log n) 内查找。
- 求「**最小化最大值 / 最大化最小值**」——看到这两个词基本就是二分答案。
- 答案具有**单调性**：`check(x)` 为真之后一直为真（或一直为假）。这是二分答案的充分条件。
- 「第 k 小」「分割数组使……最小」这类。

## 核心思想

每次排除一半。所有二分题的混乱都来自**区间定义不统一**——所以先选一种写法，然后**永远只写这一种**。

## 一、区间写法（我用双闭 [lo, hi]）

**写作约定：我选双闭区间，全库统一用这一套。** 选它的理由：`lo`/`hi` 都是真实下标，`while (lo <= hi)` 就是「区间里还有元素」，结束条件一眼看懂；不用纠结越界位置代表什么。

### 1.1 精确查找（找一个值）

```cpp
int lo = 0, hi = (int)a.size() - 1;        // 双闭
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;          // 防溢出
    if (a[mid] == target) return mid;
    else if (a[mid] < target) lo = mid + 1;
    else hi = mid - 1;
}
return -1;
```

### 1.2 找边界（**真正的主力**）

```cpp
// 第一个 >= t 的位置（左边界 / lower_bound）
int lo = 0, hi = (int)a.size() - 1;
while (lo <= hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] >= t) hi = mid - 1;         // mid 满足 → 记下意思，左半边继续找更早的
    else             lo = mid + 1;
}
// 结束时不变量：lo == hi + 1
//   [0, lo)  的元素全部 <  t
//   [lo, n)  的元素全部 >= t
// 所以 lo 就是答案，取值 [0, n]（n 表示「插在末尾」，不是 bug）
```

**精确查找只是它的特例**：先找左边界，再看 `a[lo] == target` 成不成立。

### 1.3 判定符号 → 决定你拿到哪条边界

这是这套写法的核心，值得单独记：

| 循环里写 | 结束时 `lo` 是 | 用途 |
| --- | --- | --- |
| `if (a[mid] >= t) hi = mid - 1;` | 第一个 **≥ t** 的位置 | 左边界 |
| `if (a[mid] >  t) hi = mid - 1;` | 第一个 **> t** 的位置 | 减一 → 右边界 = 最后一个 ≤ t |

一句话：**`>=` 出第一个，`>` 出最后一个（的下一格）**。

为什么？因为不变量里的「往左缩」条件就是你想要的边界的定义式：

> `[0, lo)` 全部满足「往左缩的条件」，`[lo, n)` 全部不满足；`lo` 是第一个不满足的位置。

所以「第一个 ≥ t」就把条件写成 `a[mid] >= t`，「第一个 > t」就写成 `a[mid] > t`。**不用背两套模板，背一个不变量，条件按需换符号。**

推论：`lower_bound = 第一个 >= t`，`upper_bound = 第一个 > t`，所以 `upper - lower` = t 出现的次数。

### 1.4 另一套写法（左闭右开 [lo, hi)）——知道就行，我不常用

```cpp
int lo = 0, hi = (int)a.size();            // [lo, hi)
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (a[mid] < target) lo = mid + 1;
    else                 hi = mid;
}
return lo;
```

好处是 `lo`/`hi` 含义统一（都是「答案所在区间的边界」），坏处是 `hi` 初值要写 `n` 而不是 `n-1`，容易和双闭搞混。

**两套写法绝对不能混**：`while (lo <= hi)` 配 `hi = mid` 会死循环；`while (lo < hi)` 配 `hi = mid - 1` 会漏答案。混用的症状是「有的用例过、有的超时」，特别难查。

## 二、std::lower_bound / upper_bound

```cpp
auto it = lower_bound(a.begin(), a.end(), target);
if (it != a.end() && *it == target) { /* 找到 */ }
int idx = (int)(it - a.begin());
```

- 要求区间**已按 `<` 排好序**（或传入自定义比较器）。
- 自定义结构体要能比较，或者传 lambda 作第三个参数。
- `set` / `map` 用成员函数 `s.lower_bound(x)`（O(log n)），别用 `std::lower_bound(s.begin(), s.end(), x)`（那是 O(n)）。

## 三、二分答案（模板题级别的重要）

**把「求最优值」转成「判定这个值行不行」**：

```cpp
// 求最小的 x，使 check(x) 为真；check 单调：假…假 真…真
int lo = minPossible, hi = maxPossible, ans = -1;
while (lo <= hi) {                       // 双闭
    int mid = lo + (hi - lo) / 2;
    if (check(mid)) { ans = mid; hi = mid - 1; }   // 可行：记下来，再往小了试
    else              lo = mid + 1;                // 不可行：答案只可能在右边
}
return ans;
```

求**最大的** x 使 `check` 为真时，只把 `hi = mid - 1` 换成 `lo = mid + 1`：

```cpp
if (check(mid)) { ans = mid; lo = mid + 1; }   // 可行：往大了试
else             hi = mid - 1;
```

用「`ans` 记下每次可行性、`while (lo <= hi)` 双闭」这个写法，**不需要纠结上取整/下取整**——因为 `mid` 是被显式记录或排除的，不会出现「`lo`、`hi` 相邻时 `mid` 永远等于 `lo`」的死循环。这比 `while (lo < hi)` + `lo = mid` 的写法省心，我改成这个了。

判断能不能二分答案的三个条件：

1. 答案是一个范围里的整数/浮点数（有上下界）。
2. 有 `check(x)` 判定函数。
3. `check` 单调（真之后一直真，或一直假）。

典型：爱吃香蕉的珂珂（速度）、分割数组的最大值（子数组和上限）、在 D 天内送达包裹（船载重量）。

浮点二分：固定循环 100 次，比 `while (hi - lo > 1e-9)` 稳。

## 易错点

- 两套区间写法混用 → 死循环或漏解（最高频）。双闭就配 `mid ± 1`，半开就配 `hi = mid`。
- `mid` 用 `(lo + hi) / 2` 溢出。
- `hi` 初值取 `n` 还是 `n - 1`，跟区间开闭必须一致（双闭是 `n - 1`）。
- **找边界时结果可能 == n**（target 比所有元素都大），判「找到没」必须先 `if (lo == n)` 再取 `a[lo]`。
- **判定符号直接决定找到哪条边界**：`>=` 出左边界，`>` 出右边界（的下一格）。想在 target 存在时取右边界却写了 `>=`，答案是错的而不是「差一点」。
- 求出边界后忘了核对 `a[lo] == target`——「第一个 ≥ t 的位置」在 t 不存在时也有值，那是插入位置。
- 精确查找写 `while (lo < hi)` → 区间只剩一个元素时直接退出，`[target]` 这种输入查不到。
- 二分答案的 `check` 里自己写错（比如用 int 累加溢出）→ 用 `long long`。
- 旋转数组：先判断哪半边有序，再决定往哪边收缩；有重复元素时最坏退化成 O(n)。
- 有重复元素求「第一个/最后一个」位置，用 `lower/upper_bound` 组合，别自己写「找到后左右扩」（退化成 O(n)）。
