# 哈希表

## 什么时候想到它（识别信号）

- 需要 **O(1) 查询「之前出现过吗 / 出现几次 / 第一次出现在哪」**。
- 两层循环枚举会超时，而内层循环只是在「查找」某个值 → 用哈希把内层降到 O(1)。
- 要判**重复 / 同构 / 异位词** → 把「特征」哈希成一个键。
- 要求 O(n) 且空间可以换时间。

反过来：如果只需判存在性且数据有序，先想双指针；如果需要**前驱后继/范围查询**，哈希不行，要 `set` / 树。

## C++ 的两个容器

```cpp
unordered_map<int, int> mp;      // 值 -> 下标 / 次数
unordered_set<int> st;           // 只判存在
mp.reserve(n * 2);               // 预分配桶，避免反复 rehash（大用例能快不少）
```

| 需求 | 写法 |
| --- | --- |
| 判存在 | `st.count(x)` |
| 查值 | `auto it = mp.find(k); if (it != mp.end()) ...` |
| 取或插 | `mp[k]`（**会插入**，见易错点） |
| 计数 | `++mp[x];` |
| 删除 | `mp.erase(k);` |

## 套路

### 1. 一次遍历 + 边存边查（最优）

```cpp
unordered_map<int, int> seen;
for (int i = 0; i < n; ++i) {
    auto it = seen.find(target - a[i]);   // 先查
    if (it != seen.end()) return {it->second, i};
    seen[a[i]] = i;                       // 后存
}
```

**先查后存**是关键：先存会把当前元素也放进表，导致自己配自己。

### 2. 把「特征」做成键

- 字母异位词：把 `string` 排序后当 key（`sort(s.begin(), s.end())`）。
- 同构字符串：双向映射，两个 `unordered_map` 互相校验。
- **复合键**（`pair` / 元组 / 坐标）：C++ 的 `unordered_map` 没有现成的 hash。两种办法：
  - 编码成一个整数：`(long long)x * 100000 + y`；
  - 自定义 hash 结构体传给第三个模板参数。

```cpp
struct PairHash {
    size_t operator()(const pair<int,int>& p) const {
        return hash<long long>()(((long long)p.first << 32) ^ p.second);
    }
};
unordered_map<pair<int,int>, int, PairHash> mp;
```

### 3. 用哈希表做「索引」加速查找

「两数之和」存值→下标；「最长连续序列」把 `unordered_set` 当存在性判断，只从「序列起点」（`x-1` 不在集合里）开始往右数，均摊 O(n)。

## 易错点

- **`mp[k]` 会插入**：用 `if (mp[x])` 判存在是错的（值可能本来就是 0），必须用 `count` / `find`。而且这一下标访问会插入 `{k, 0}`，把 `size()` 搞脏。
- **遍历中删除**：`for (auto &p : mp) mp.erase(p.first);` 是 UB，必须 `for (auto it = mp.begin(); it != mp.end(); ) { if (...) it = mp.erase(it); else ++it; }`。
- `unordered_map` 的迭代顺序**不保证**与插入顺序一致（和 Python dict 不同），要按插入顺序就得另存一个 `vector`。
- 自定义 key 需要提供 hash，`vector<int>` 直接当 key 编译不过。
- 最坏情况哈希冲突退化到 O(n)，LC 有专门的卡哈希用例；被卡时换 `map` 或加随机盐。
- `reserve` 不是必须，但大用例能省掉多次扩容。
